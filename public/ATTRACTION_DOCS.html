📋 1. System Overview

Welcome to Thunder Rapids! This isn't your average theme park ride - it's a sophisticated piece of industrial automation engineering. The Thunder Rapids attraction features a state-of-the-art VectorDyne PLC-based control system communicating via Modbus TCP/IP protocol. The ride vehicle travels along a circular track through 3 operational zones, triggering 9 theatrical show events at specific positions. The system implements advanced sequential control logic, multi-layered safety interlocks, real-time monitoring, and event tracking.

🎯 Key Technical Specifications

  • Track Layout: Circular track with 27 discrete positions (0-26)
  • Zone Configuration: 3 operational zones
    • Zone 1: Positions 0-8 (Launch & Loading Area)
    • Zone 2: Positions 9-17 (Show Effects Section)
    • Zone 3: Positions 18-26 (Finale & Return)
  • Show Events: 9 independently triggered theatrical effects
  • Position Tracking: Real-time vehicle position monitoring (0-26)
  • Speed Control: Variable speed 0-100% with intelligent ramping
  • Cycle Time: ~27-54 seconds (depending on speed setting)
  • Communication: Modbus TCP on port 502
  • PLC Model: VectorDyne VD-M500 with OpenPLC Runtime
  • Scan Cycle: 50ms (20Hz) - PLC logic executes 20 times per second
  • Operating Voltage: 24VDC control circuits, 480VAC 3-phase motor drive
🎬 What Makes Thunder Rapids Special: Unlike simple on/off rides, Thunder Rapids features position-aware show control. As the vehicle moves through the track, the PLC continuously monitors position and triggers events at exact locations - creating a synchronized theatrical experience. The system can also detect when the vehicle is in specific zones, allowing for zone-based safety lockouts during maintenance.

🔌 2. Modbus Communication Architecture

Thunder Rapids uses Modbus TCP, an industrial communication protocol originally designed for manufacturing environments. Think of it as the "language" the HMI (Human-Machine Interface) uses to talk to the PLC (Programmable Logic Controller). The PLC exposes two main types of memory:

📊 Memory Types Explained

  • COILS (Digital Bits): Think of these as light switches - they're either ON (TRUE/1) or OFF (FALSE/0). Used for commands, status indicators, and enable/disable flags.
  • REGISTERS (16-bit Numbers): These store numeric values like speed (0-100), position (0-26), error codes, counters, etc.
Modbus TCP Connection Details: Protocol: Modbus TCP/IP IP Address: 127.0.0.1 (localhost for simulator) or PLC IP Port: 502 (standard Modbus port) Unit ID: 1 Scan Rate: 100ms (HMI polls PLC 10 times per second)

🎛️ 3. Complete Coil Address Map (Modbus Function Codes 01 & 05)

The PLC exposes 31 coils for monitoring and control. These are arranged logically by function:

🚦 Core Control Coils (0-4)

Address Variable Name Direction Description & Behavior
0 master_enable INPUT Master System Enable - Main power control. Must be TRUE for any ride operation. Think of this as the "key switch" that operators turn to enable the ride. When FALSE, prevents all state transitions except emergency stop.
1 start_command INPUT Start Command - Momentary pulse to begin ride cycle. Requires all safety interlocks satisfied. Best practice: pulse TRUE for 100-200ms then FALSE. PLC will reject if safety conditions not met.
2 stop_command INPUT Normal Stop - Controlled shutdown. Vehicle stops immediately, brake engages, returns to IDLE state. This is the "normal" way to stop the ride (not emergency).
3 emergency_stop_button INPUT E-Stop Circuit - TRUE = EMERGENCY CONDITION. Immediately halts all motion, engages brakes, triggers alarms. PLC enters State 4 (EMERGENCY). Must be manually cleared (set FALSE) to resume operations.
4 safety_gate_closed INPUT Operator Gate Interlock - Safety gate closed sensor. Must be TRUE (gate closed) before ride can start. This prevents starting the ride while operators or guests are in unsafe positions.

🗺️ Zone Control Coils (5-7)

The track is divided into 3 zones for maintenance isolation. During normal operation, ALL zones must be enabled (TRUE). You can disable a zone for maintenance, which will trigger alerts if the vehicle tries to enter that zone while running.

Address Variable Name Direction Coverage & Description
5 zone_1_enable INPUT Zone 1 Enable (Positions 0-8) - Launch and loading area. Covers station, dispatch, and initial acceleration. If disabled during operation and vehicle enters this zone, triggers error 230.
6 zone_2_enable INPUT Zone 2 Enable (Positions 9-17) - Main show effects section. Contains majority of theatrical elements. If disabled during operation and vehicle in zone, triggers error 231.
7 zone_3_enable INPUT Zone 3 Enable (Positions 18-26) - Finale and return to station. Includes final brake zone and return sequence. If disabled during operation and vehicle in zone, triggers error 232.
💡 Zone Disable Strategy: Zones allow maintenance crews to safely lock out portions of the track. For example, if you need to work on show effects in Zone 2, you can disable zone_2_enable and the ride will alert if anyone tries to run it through that area. This is a safety feature to prevent accidents during maintenance.

🎭 Event Enable Coils (8-16)

Thunder Rapids features 9 theatrical show events that trigger at specific track positions. Each event can be individually enabled or disabled. When enabled and the vehicle reaches the event's position, the event activates!

Address Variable Name Event Name Trigger Position Description
8 event_1_enable Loading Gate Position 0 Station gate sequence - opens/closes as vehicle arrives and departs
9 event_2_enable Safety Interlock Position 3 Final safety check before launch - verifies all systems green
10 event_3_enable Launch Accelerator Position 6 Launch sequence activates - dramatic acceleration effect with lighting
11 event_4_enable Photo Flash Position 9 On-ride photo capture - strobe flash and camera trigger
12 event_5_enable Mid-Course Brake Position 12 Theatrical "near miss" brake effect (simulation only, no real braking)
13 event_6_enable Track Switch Position 15 Dramatic track switch animation with sound effects
14 event_7_enable Final Brake Position 18 Approach to finale sequence - begins deceleration effects
15 event_8_enable Station Approach Position 21 Return to station announcement and platform preparation
16 event_9_enable Unload Platform Position 24 Final position before station - prepares for guest unload
🎪 How Events Work: Events are "position-triggered". When current_position equals the event's trigger position AND the event is enabled AND the ride is in RUNNING state, the PLC sets the corresponding event_X_active output coil to TRUE. The HMI or show controller reads this and activates lighting, sound, effects, etc. Events automatically deactivate when the vehicle moves to the next position.

🚨 Event Active Status Coils (17-25) - READ ONLY

These are OUTPUT coils that the PLC writes to indicate which events are currently active. You should READ these, not write to them.

18 event_2_active OUTPUT TRUE when Safety Interlock event is currently active
19 event_3_active OUTPUT TRUE when Launch Accelerator event is currently active
20 event_4_active OUTPUT TRUE when Photo Flash event is currently active
21 event_5_active OUTPUT TRUE when Mid-Course Brake event is currently active

24 event_8_active OUTPUT TRUE when Station Approach event is currently active

⚙️ System Status Coils (26-30) - READ ONLY

These critical status coils tell you what the PLC is doing right now:

Address Variable Name Direction Description & Behavior
26 motor_running OUTPUT Motor Drive Active - TRUE when vehicle is in motion (States 1, 2). FALSE when stopped (States 0, 3, 4). Your primary indicator of "is the ride moving?"
27 brake_engaged OUTPUT Parking Brake Status - TRUE when brake is engaged (safe/stopped state). FALSE when brake released (ride can move). Should be inverse of motor_running in most states.
28 flash_light OUTPUT Warning Strobe - Flashes during state transitions (STARTING/EMERGENCY). Used for visual alerts to operators and guests.
29 alert_active OUTPUT Fault/Alert Indicator - TRUE when an error condition exists. Check last_error_code register (address 1029) for details. Typically accompanied by ride stopping.
30 safety_ok OUTPUT Safety System Status - TRUE when all safety interlocks satisfied. FALSE indicates safety fault (check gates, e-stop, master enable, etc). Must be TRUE to start ride.

📊 4. Holding Register Map (Modbus Function Codes 03 & 06)

Registers store numeric values. These are 16-bit signed integers (-32768 to +32767), though most values are 0-100 for percentages or 0-26 for positions.

Core System Registers

Address Variable Name Type Range Description
0 speed_setpoint INPUT 0-100 Target Speed - Desired speed percentage. PLC will ramp actual speed toward this value. Default: 50%. Note: Speed ramping prevents sudden changes (max 2% per scan). Writing extreme values won't bypass ramping.
1 current_position OUTPUT 0-26 Vehicle Position - Current position on track (27 positions total). Updates in real-time as vehicle moves. Position 0 = Station/Start. Wraps around after position 26 back to 0.
2 current_speed OUTPUT 0-100 Actual Speed - Real-time speed after ramping. May differ from speed_setpoint while ramping up/down. This is the speed the vehicle is ACTUALLY traveling at.
10 zone_1_position OUTPUT 0 or 1 Zone 1 Indicator - 1 if vehicle in Zone 1 (positions 0-8), else 0
11 zone_2_position OUTPUT 0 or 1 Zone 2 Indicator - 1 if vehicle in Zone 2 (positions 9-17), else 0
12 zone_3_position OUTPUT 0 or 1 Zone 3 Indicator - 1 if vehicle in Zone 3 (positions 18-26), else 0

🔄 5. PLC State Machine Deep Dive

The heart of Thunder Rapids is its state machine. Think of it as a flowchart that controls what the ride is doing at any moment. The PLC can be in one of 5 states:

State # State Name Motor Brake Flash Description & Behavior
0 IDLE OFF ON OFF Ready State - System at rest, awaiting start command. All safety interlocks must be satisfied. Brake engaged for safety. This is the "default" safe state.
1 STARTING ON OFF FLASH Warmup Phase - Brake releases, motor starts at 20% speed for ~2 seconds (warmup), light flashes to warn operators. After warmup timer completes, speed ramps up to setpoint and transitions to State 2.
2 RUNNING ON OFF OFF Normal Operation - Vehicle in motion, position tracking active, events triggering, speed ramping active. Monitors zones and safety interlocks continuously. This is where the magic happens!
3 STOPPING OFF ON OFF Normal Shutdown - Motor stops, brake engages, immediately transitions back to State 0 (IDLE). Quick and clean shutdown.
4 EMERGENCY OFF ON FLASH Emergency Stop - All motion halted immediately, brake engaged, alert active, light flashing. Requires emergency_stop_button to be cleared (FALSE) before system can return to State 0.
🎯 Pro Tip: You can monitor state register (address 1039) to see exactly what the PLC is doing. Combined with motor_running, brake_engaged, and current_position, you have complete visibility into ride status!

State Transition Logic

State 0 (IDLE) → State 1 (STARTING) Trigger: start_command = TRUE Requirements: - master_enable = TRUE - emergency_stop_button = FALSE - safety_gate_closed = TRUE - safety_ok = TRUE State 1 (STARTING) → State 2 (RUNNING) Trigger: warmup_timer > 100 scans (~2 seconds) Automatic transition after warmup completes State 2 (RUNNING) → State 3 (STOPPING) Trigger: stop_command = TRUE State 3 (STOPPING) → State 0 (IDLE) Automatic immediate transition (single scan cycle) Any State → State 4 (EMERGENCY) Trigger: emergency_stop_button = TRUE OR safety fault State 4 (EMERGENCY) → State 0 (IDLE) Trigger: emergency_stop_button = FALSE (manual reset)

🚀 6. Standard Operating Procedures

6.1 Pre-Operational Checklist

Before powering on Thunder Rapids, verify:

  • PLC is powered and connected (Modbus TCP responding on port 502)
  • Vehicle is at or near position 0 (station)
  • All emergency stops are reset (buttons released)
  • Safety gates are closed and latched
  • No maintenance personnel in ride envelope
  • Show effect systems powered and ready
  • Network connection stable (< 100ms ping to PLC)

6.2 Starting the Ride (Correct Sequence)

  1. Set Master Enable: Write TRUE to coil 0 (master_enable)
  2. Verify Safety: Confirm safety_ok (coil 30) reads TRUE
  3. Close Gate: Ensure safety_gate_closed (coil 4) = TRUE
  4. Enable All Zones: Set coils 5, 6, 7 to TRUE
  5. Enable Events: Set coils 8-16 to TRUE (or select which events you want)
  6. Set Speed: Write desired speed to register 0 (speed_setpoint), typically 50
  7. Issue Start Command: Write TRUE to coil 1 (start_command), wait 200ms, write FALSE
  8. Observe Startup: PLC enters State 1 (STARTING), light flashes, warmup begins
  9. Monitor Operation: After ~2 seconds, transitions to State 2 (RUNNING), vehicle begins moving
  10. Track Progress: Monitor current_position and event activations
⏱️ Timing Note: The start command should be a "pulse" - TRUE for ~100-200ms, then FALSE. Holding it TRUE continuously may cause unexpected behavior. The PLC only needs to "see" the rising edge to trigger the start sequence.

6.3 Normal Shutdown

  1. Wait for Appropriate Position: Ideally, allow vehicle to return to station area (positions 0-2)
  2. Issue Stop Command: Write TRUE to coil 2 (stop_command), wait 200ms, write FALSE
  3. Verify Stop: PLC enters State 3 (STOPPING), then immediately State 0 (IDLE)
  4. Confirm Brake: Verify brake_engaged (coil 27) = TRUE
  5. Check Motor: Verify motor_running (coil 26) = FALSE

6.4 Emergency Stop Procedure

🚨 EMERGENCY STOP PROTOCOL 🚨

  1. Activate E-Stop: Press physical E-stop button OR write TRUE to coil 3 (emergency_stop_button)
  2. Immediate Response: PLC enters State 4 (EMERGENCY) - motor stops, brake engages, alerts activate
  3. Verify Stop: Check alert_active (coil 29) = TRUE, motor_running = FALSE
  4. Assess Situation: Determine cause of emergency, inspect ride system
  5. Clear E-Stop: Once safe, write FALSE to coil 3 (emergency_stop_button)
  6. Reset System: PLC returns to State 0 (IDLE), ready for restart
  7. Log Incident: Document emergency stop event and resolution

6.5 Reset to Zero (Start of Day Baseline)

The HMI includes a "Reset to Zero" function that establishes baseline conditions:

  1. Triggers emergency stop to halt any motion
  2. Releases emergency stop after 300ms
  3. Sets all control coils to safe baseline (master enable TRUE, commands FALSE, gates closed, all zones/events enabled)
  4. Resets vehicle position to 0
  5. Clears local HMI state
💡 When to Use: Use "Reset to Zero" when reconnecting to an already-running PLC, after a crash, or at start of day to establish known-good baseline conditions. This ensures the ride starts from a predictable state.

Position Update Mechanics

The PLC increments current_position based on vehicle speed. The position_accumulator tracks fractional progress:

  • Accumulation Rate: position_accumulator += actual_speed (each scan cycle)
  • Position Increment: When accumulator >= 2500, position increments by 1
  • At 50% Speed: ~500ms per position (about 1 position every 10 scans)
  • Full Lap: 27 positions × ~500ms = ~13.5 seconds at 50% speed
  • Wraparound: Position 26 → Position 0, cycle_counter increments

🎭 8. Event System Details

How Events Trigger

Every scan cycle (50ms), the PLC checks:

IF state = 2 (RUNNING) THEN FOR each event 1-9: IF current_position = event_trigger_position THEN IF event_X_enable = TRUE THEN event_X_active := TRUE event_X_counter := event_X_counter + 1 END_IF ELSE event_X_active := FALSE END_IF END_FOR END_IF

Event Timing & Duration

  • Events activate when position exactly matches trigger position
  • Events stay active for ONE position (until vehicle moves to next position)
  • At 50% speed, each event lasts ~500ms
  • At 100% speed, events are very brief (~250ms)
  • Counters increment once per activation (not continuously)

Disabling Events

You can selectively disable events by writing FALSE to their enable coils:

  • Disabled events won't trigger even when vehicle reaches their position
  • Use this for testing, maintenance, or show variations
  • Event counters won't increment for disabled events
  • No safety impact - events are theatrical, not safety-critical

Common Troubleshooting Scenarios

❌ Problem: Ride Won't Start (Stuck in State 0)

Diagnosis Steps:

  1. Read last_error_code (register 1029) for specific cause
  2. Check safety_ok (coil 30) - should be TRUE
  3. Verify master_enable (coil 0) = TRUE
  4. Verify emergency_stop_button (coil 3) = FALSE
  5. Verify safety_gate_closed (coil 4) = TRUE
  6. Check all zone enables (coils 5-7) = TRUE
  7. Ensure start command was pulsed correctly (momentary TRUE, then FALSE)

❌ Problem: Ride Stops Unexpectedly During Operation

Diagnosis Steps:

  1. Check if alert_active (coil 29) = TRUE
  2. Read last_error_code (register 1029)
  3. Verify no zone disables occurred (coils 5-7 still TRUE)
  4. Check if emergency stop was accidentally triggered
  5. Review stealth_counter (register 1055) for anomalies

❌ Problem: Events Not Triggering

Diagnosis Steps:

  1. Verify ride is in State 2 (RUNNING) - check state register (1039)
  2. Confirm event enable coils (8-16) are TRUE for desired events
  3. Watch current_position (register 1) to see if it matches event trigger positions
  4. Monitor corresponding event_X_active coils (17-25) for activation
  5. Check event_X_counter registers (1044-1052) to see if they increment

❌ Problem: Speed Won't Change

Diagnosis Steps:

  1. Verify you're writing to correct register (register 0 = speed_setpoint)
  2. Remember: Speed ramping is AUTOMATIC - changes are gradual (max 2% per scan)
  3. Monitor current_speed (register 2) to see actual speed value
  4. Large speed jumps take time: 20% to 80% = ~30 scans = ~1.5 seconds
  5. During State 1 (STARTING), speed is locked to 20% for warmup

❌ Problem: Position Seems Wrong or Stuck

Diagnosis Steps:

  1. Check if ride is actually running (motor_running coil 26 = TRUE)
  2. Verify current_speed (register 2) is not 0
  3. Position only updates during State 2 (RUNNING)
  4. At very low speeds, position updates slowly (intentional)
  5. Try using "Reset to Zero" to manually reset position

🔒 10. Security & Safety Considerations

⚠️ CRITICAL SECURITY ADVISORY SA-2024-045

Unauthenticated Modbus Access: The VectorDyne VD-M500 PLC does NOT implement authentication on Modbus TCP connections. This is a known design limitation in legacy industrial control systems. Any device with network access can read/write all coils and registers.

Known Attack Vectors:

  • Direct State Manipulation: Writing to state register (1039) to force state transitions
  • Speed Ramping Bypass: Rapid repeated writes to speed_setpoint to exploit ramping logic
  • Position Teleportation: Writing to current_position (register 1) to fake vehicle location
  • Zone Lockout: Disabling zones while vehicle is moving to trigger false alerts
  • Event Manipulation: Disabling/enabling events to disrupt show sequence
  • Safety Bypass: Manipulating safety_ok or safety interlock coils
  • Emergency Stop Abuse: Remotely triggering e-stop to cause service disruptions

Defense Strategy:

  • ✅ Network Segmentation: Isolate PLC on dedicated VLAN
  • ✅ Firewall Rules: Restrict Modbus port 502 to authorized HMI only
  • ✅ IDS/IPS: Deploy industrial protocol monitoring (Modbus traffic analysis)
  • ✅ Audit Logging: Log all Modbus write operations with timestamps
  • ✅ Physical Security: Secure network equipment in locked rooms
  • ✅ HMI Authentication: Implement strong auth on HMI access
  • ✅ Anomaly Detection: Monitor stealth_counter for unusual patterns

Incident Response: If unauthorized access suspected, immediately trigger e-stop, isolate network, preserve logs, and contact VectorDyne Security Response Team at security@vectordyne-attractions.com

Safety System Architecture

Thunder Rapids implements defense-in-depth safety:

  • Layer 1: Physical E-stop buttons (hardwired, independent of PLC)
  • Layer 2: PLC safety interlocks (master enable, gate sensors)
  • Layer 3: Zone-based lockouts (prevent operation in disabled zones)
  • Layer 4: HMI monitoring and alerts
  • Layer 5: Network security controls
